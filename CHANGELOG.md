# Changelog

What changed in each release, newest first. Each release's page on [GitHub](https://github.com/Adityasharma0101911/Endo-s-Unified-Downloader/releases) has its files and the full notes.

## Unreleased

- **Recent folders.** Beside Save to on the Add page, the last 5 folders downloads were saved to are one click away.
- **Rules per site.** Settings > Speed > Rules per site: for a site and its subdomains, how many of its downloads run at once, the connections of a download added from it, and the seconds from one of its files starting or ending to the next starting (0 leaves one as set for all). Saved with the settings.
- **More downloads at once while the line has room.** While the downloads running take under half of what your line was seen to carry (servers that each cap their speed leave it so) and more wait, the queue starts one more than "Downloads at once", another 15 s later, 3 more at most, and none more once they fill 80% of it. Settings > Speed > "More at once while the line has room", on by default. Nothing more starts before the app has seen the line's speed, nor with one at a time, and a host's connection limit and the rules per site still hold.
- **The same file from two places, one download.** A link added while another download has a file of its name and size from another host waits, and its card offers to download the one file from both servers together instead of fetching two copies; never without asking.
- **The system's proxy.** When neither the app nor the environment names a proxy, downloads go through the one this computer's settings name: Windows' Internet settings, macOS's network settings, GNOME's or KDE's on Linux; helper tools follow it too, and what may not go through a proxy is refused under it as under any other. A setup script (PAC) is not run. Settings > Network > "Use the system's proxy" (on by default) says which proxy is in use; `--no-proxy` goes direct.
- **Ranges in a link.** `https://example.com/img[001-120].jpg` adds `img001.jpg` to `img120.jpg`, zero padding kept, and so do `[1-20]`, `[a-f]` and a step, `[0-100:10]`, as curl writes them: on the command line, in a batch file, and in the app's link bar (whose card says how many links it stands for), Add many links…, a paste and a dropped `.txt`. At most 10,000 links from one link; an IPv6 host and brackets in a query string are left alone.
- **One download's speed limit and connections, changed while it runs.** Under For this download in a download's details, a speed limit and a number of connections for it alone take effect as soon as you press Apply, without pausing or starting it again, and stay with it across pauses and restarts. The limit for all downloads still holds over it; its connections are the most the Autopilot may open. Why is it slow? names its own limit when that is what holds it.
- **A notification when downloads end.** While the window is not in front, a download that finishes says so in a system notification (its name and folder), and one that fails says why, in the words its card uses; downloads that end together share one, with a count, and there is at most one every 20 seconds. A Windows toast (a click brings the window up), the macOS Notification Center, the desktop's notification server on Linux. Settings > Desktop and schedule > "Notify when downloads end" (on by default) and "Only when one fails".
- **Downloads wait on a metered connection.** While the system says the connection is metered (Windows, and Linux through NetworkManager), the app holds queued downloads and a banner says why, with Download all anyway; Start on a card downloads that one anyway, and running downloads go on. Settings > Desktop and schedule > "Wait on a metered connection" (on by default) turns it off; it holds nothing where the system never says a connection is metered. The command line only says so, and downloads.
- **Go easy while you use the PC (Windows).** Settings > Desktop and schedule > "Go easy while I use this PC" (off by default), and `--go-easy` on the command line: downloads are written and checked at low disk and memory priority, so a large one no longer pushes your own files out of memory or holds up a game's reads, and while the window is minimized or in the tray the app runs in the system's efficiency mode. On a local server the disk and memory part cost nothing measurable (512 MiB in 412 ms against 409 ms), nor did efficiency mode at a gigabit line's speed (256 MiB in 2.38 s against 2.37 s); at 1.3 GB/s efficiency mode makes a download about 40% slower, so the setting is off by default. The network is not part of it, see the README.
- **A network that goes away no longer fails downloads.** When the system says this computer has lost its network or the internet, a download stops counting its tries and waits, shown as "waiting for the network", and goes on as soon as the network is back (at once on Windows, which tells the app), for up to 2 hours. In the app, a download that failed for want of an answer goes back in the queue by itself, after 1, then 5, then 25 minutes, three times at most; never one refused, one that failed its checksum or ran out of disk space. Only the system is asked, never another host.
- **The computer stays awake for your downloads.** While downloads run, and in the 12 hours before the schedule starts downloads waiting for it, the computer no longer goes to sleep by itself; the moment there are none, it may again. The screen still turns off, and you can still put it to sleep. Settings > Desktop and schedule > "Keep the computer awake" (on by default); the command line keeps it awake while it runs, unless `--allow-sleep`.
- **Small downloads finish sooner.** The checksum files a site may publish beside a download are asked for two at a time instead of one by one, so a file that has already arrived waits about half as long for them. A folder seen to publish none is remembered for ten minutes: the rest of a batch from it skips those requests.
- **Saving the resume state no longer pauses a download.** The flush to disk every 2 seconds runs beside the download, through a file handle of its own, instead of holding up the connections' writes and the progress shown. On a local server at 256 MB/s a 768 MiB file came in 3.29 s instead of 3.43 s, and the progress no longer froze for up to a third of a second at each save.
- **The site's checksum is taken as the file arrives.** A checksum a site publishes (in its answer's headers, its Metalink or a checksum file) is now computed over the file while it downloads, as yours is, from the moment it is known, instead of reading the whole file again once it is done. On a local server at 256 MB/s a 768 MiB file with the site's SHA-256 came in 3.58 s instead of 3.69 s, as fast as with that SHA-256 given as yours.
- **A request that is never answered no longer holds a download up.** When a request for part of a file has had no answer for 3 seconds (or 8 times as long as that server takes to answer, if longer) while the server answered other requests since, the part is asked for once more over another connection, and the first answer takes it, instead of waiting out the 30-second stall timeout; never under a speed limit, and never past the server's connection limit. And a connection that slows down near its end is now split by its speed over the last 5 seconds, not by its average.
- **Faster from servers that only speak HTTP/2.** A download from one, once a download from it went over HTTP/2, spreads its requests over up to 4 HTTP/2 connections instead of multiplexing them all over one: on a local HTTP/2 server with 16 connections asked for, 128 MiB came at 55 MB/s instead of 42 over a 100 ms round trip, and at 195 MB/s instead of 133 over a 20 ms one (with the Autopilot, 54 instead of 43, and 202 instead of 166).
- **Finished files on Windows are ordinary files.** The `.part` file is sparse while it downloads, so that writes far into it do not first fill it with zeros; once complete it is made an ordinary file again before taking its name, as copy, backup and virtual machine tools expect.

## 2.2.0 (2026-11-19)

- **A new look for the app.** One bar at the top of Downloads takes anything pasted or dropped (Ctrl+V anywhere still adds a copied link at once), and a card under it says in plain words what it is, where it comes from and what it needs, with the two or three choices that matter for it and one Download button; More options holds the rest. Downloads are cards with their pieces filling in along the bar, a plain status line, and their details beside the list on a wide window (in its place on a narrow one): the connections with their servers, the mirrors and the fastest, what the file is checked against, where it came from, what happened to it, and a speed limit for it alone. A pulse bar over every page shows the speed of everything together, how many downloads run, wait and are done, Pause all and the speed limit's switch. The pages are Downloads, Library (the history, grouped by day, searchable, ten thousand rows as smooth as twenty), Sources (every kind of link the app takes, what each needs, an example to try, and the helper tools) and Settings (in groups, searchable, with Appearance new). Ctrl+K opens a command palette; Up, Down, Enter, Space and Delete drive the list from the keyboard. A web page's card can also save the page as one file that opens offline (Keep its scripts under More options), into the save folder and the Library. Behind the pages a slow moving background of soft lights at three depths follows your downloads, drawn out into a current while they run (Settings > Appearance: on by default, Calm, Normal or Lively); it keeps still while the window is in the background, minimized or hidden, and under Reduce motion, when an idle window asks for no frames at all.
- **Usenet.** An NZB (a file, one dropped on the window, or a link) adds one download per file it lists, fetched over NNTP from your own provider's servers (TLS or plain, with your user name and password; `--nntp-server`, `ENDO_NNTP_*`, or Settings > Usenet servers): several articles asked for at once on each connection, a server's connection limit shared by all its downloads, yEnc-decoded and checked by CRC-32, written in place out of order; an article one server lacks or holds damaged comes from the next, and so do all of a server's when it refuses every connection or asks to sign in (which it says); a download cut short goes on with the articles it lacks. A file is done only when its articles cover all of it; one failing its CRC-32 downloads again on the next try. Files are named by the NZB's subject, their yEnc header, or the PAR2 set beside them, never over a file already there, and checked against that set (checked, not repaired: a damaged file stays a `.part`, checked again on the next try). The NZB is kept in the app's data folder, so the queue holds no indexer link or key. A multi-volume RAR set is left packed.
- **Game mods.** Modrinth projects, versions and modpacks (any `.mrpack` with `modpack:` before its link; a plain `.mrpack` link downloads the file), with their SHA-512, picked by game version and loader through `--formats`; a modpack's files to the paths it states, its overrides unpacked out of the pack once it matches Modrinth's SHA-512, never over a file already in the folder. CurseForge files and modpacks through its API with your key (`--curseforge-key`), which never follows a redirect to another host, and not through a proxy, which its API terms forbid; a file its author keeps to CurseForge's site is its page to open. Thunderstore packages with their dependencies. A Nexus Mods page or `nxm://` link names the page to open, whose download button the extension hands to the app: Nexus Mods' terms forbid personal API keys in public apps.
- **Ollama models.** `ollama.com` model pages and `ollama://` links download from Ollama's registry, each layer checked by SHA-256: the model as a readable `.gguf` with its template, parameters and licences beside it, or, saved into an Ollama models folder, its blobs and manifest where Ollama keeps them.
- **Open-access papers.** A DOI, its doi.org link or a publisher's page that holds it downloads the paper's legal open copy: through Unpaywall with the email you set (`--unpaywall-email`), the arXiv, PubMed Central or Zenodo copy it names, else the published version's PDF the DOI's record links under a Creative Commons licence already in force; with no open copy, the paper's page. A publisher's direct file link (`/doi/pdf/...`) downloads as any link does. PubMed Central articles from its open-access set with their MD5, and bioRxiv and medRxiv preprints as PDFs.
- **Package registries.** Package pages on Maven Central (and `group:artifact[:version]` as typed), NuGet, pkg.go.dev, Homebrew, Flathub, anaconda.org, RubyGems, Packagist and F-Droid download their files with the checksums the registry publishes: jars and POMs with their SHA-1, `.nupkg` with its SHA-512, a Go module's zip and `go.mod` (its `go.sum` lines shown; Go publishes no hash of the zip itself), a Homebrew bottle for this machine (or `--formats`) from GitHub's registry with its SHA-256, a Flathub app's `.flatpakref` (Flathub serves apps only through OSTree), conda builds, gems and Packagist zips with theirs, and an F-Droid APK with its SHA-256 from the checked index (read once while it is unchanged, not again for every app). Helm charts in a registry (`oci://`) download as `<chart>-<version>.tgz` with their provenance.
- **itch.io.** With your itch.io API key (`--itch-key`, or Settings), a game's page downloads its uploads through itch.io's API (with your download key for a game you own; free and pay-what-you-want ones too), and a jam's entries, a collection and your library (`itch.io/my-purchases`) one folder per game, capped and paced; `--formats` picks platforms. Each download keeps its game's page, for a new link when the one itch.io gave expires. Without a key nothing is fetched.
- **Kaggle and OpenStreetMap.** Kaggle datasets download as Kaggle's archive of them (public ones without sign-in), competitions with your `kaggle.json` (`--kaggle-json`, `~` taken as your home folder), one not joined saying so, each keeping its page for a new link when Kaggle's expires; an MD5 is checked when Kaggle's storage sends one. Geofabrik extracts come with their MD5 (unchecked when it cannot be read at the time), a region's page with its sub-regions' files from Geofabrik's index, and planet files from the mirrors their torrent lists, with their MD5, or from the swarm and the mirrors at once; listed files get none of your headers or cookies.
- **Subtitles from OpenSubtitles.** `--find-subtitles en,fr` (with `--opensubtitles-key`) after each video download, and the Library's Find subtitles button on a finished video: found by the video's hash and size, else by its title, saved beside it as `<name>.<language>.srt`, within OpenSubtitles' daily quota; your account optional (its password never saved); the API key never follows a redirect to another host. Off by default.
- **Chunk stores.** A `.caibx` or `.caidx` link (casync, desync) downloads the file or folder tree it lists from its chunk store (`--chunk-store`, else `default.castr` beside it), each chunk checked against its SHA-512/256, several at once, taking what it can from a stopped run's part file, an older version (`--delta-from`, cut as casync cuts) and `--chunk-cache`. A name already taken, file or folder, is numbered (`name (1)`), never replaced; one that would not fit on the disk or passes `--max-filesize` is refused before anything is written; the cache drops only its own chunks. A one-file torrent takes `--delta-from` too.
- **A page as one file, and WARC files.** `--save-page URL` saves a web page as a single HTML file that opens offline, with its images, style sheets, fonts and iframes put into it and its scripts left out unless `--keep-scripts` (and kept from running: a policy in the file, no event handlers, no meta refresh), as its robots.txt allows. A page on the internet gets nothing from this computer or its local network put in; the file (twice the size cap) and the requests (1000) are capped, and a file of the same name is kept (`Title (1).html`). `--warc FILE.warc.gz` with `--mirror`, `--save-page` or `--wayback` also writes what they download into a WARC 1.1 file, as received, with a CDXJ index beside it.
- **Your accounts, through helper programs.** Cloud drives (rclone), Epic Games (legendary), GOG (the app's own code), Steam (DepotDownloader) and live streams yt-dlp cannot follow (streamlink), with `accounts` in the CLI and Settings > Accounts & tools in the app: where each stands, sign-in by the service's own page or app (never a password), sign-out, the account's library. Their links (`NAME:path`, `rclone://`, `epic://`, `gog://game/ID`, `steam://app/ID`; never a web link, which any page can send through the extension) download like any other; a drive's files and GOG's installers by the engine itself, games by legendary and DepotDownloader. Each helper is the one on PATH, else the build pinned in the app, fetched from its project's release when first needed and checked by SHA-256; it runs at below-normal priority and keeps its sign-in in the app's folder (on Windows DepotDownloader keeps Steam's in .NET's storage, where it stays after signing out: revoke it with Deauthorize all other devices). Each follows the proxy setting or refuses before it goes online: none takes turns through a proxy pool, and DepotDownloader goes through no proxy. `--streamlink` records a live stream with streamlink. `--doctor` lists the helpers.
- **Servers that send a version tag without quotes.** A file from a server whose ETag comes without its quotes (Azure storage, NuGet's packages) no longer fails with "remote file changed" once it is split over connections: its date names the version instead.

## 2.0.3 (2026-11-16)

- **Torrents: web seeds and the swarm at once.** A `.torrent`'s HTTP web seeds now join the swarm as peers of their own, so pieces come from the seeds and from other peers at the same time, where before the seeds' files came first and the swarm only after. Pieces are fetched from the seeds ahead of the swarm asking, a run of them in one request (up to 16 MiB, as many requests at once as the download has connections, within each host's connection limit and its rest after a 429), each checked against the torrent's SHA-1 before the torrent library gets any of it, and checked again as it is written. A piece the seeds serve wrong (the file changed since the torrent was made) or cannot serve is left to the peers while the seeds go on serving the rest (one wrong piece no longer cut every seed off for 10 seconds or more), and in a small torrent the seeds are asked for at most half the pieces at once, so the peers get some from the start. A torrent of whole pieces made by rqbit (its last piece hash is that of no bytes) keeps its piece hashes, so its seeds are peers too. Through a SOCKS5 proxy it is HTTP first and then the swarm, as before. This is an experiment, off unless the environment variable `ENDO_WEB_SEED_PEERS` is set: against archive.org it measured several times slower than its files over HTTP first, which stays the default.
- **A wrong mirror no longer costs the whole file.** When a file fails its checksum (yours, a listing's or the site's) and other mirrors sent part of it (a copy a `Link: rel=duplicate` header or a Metalink names, another archive.org server), those parts are fetched again from the server the download went by and the file is checked again, instead of the download failing and starting over.
- **One request per listed small file.** A file whose checksum is known before it starts (a listing's, or `--checksum`) is probed with its first GET alone, without a HEAD beside it: half the requests for a batch of small files (2,000 for 2,000 files in the speed benchmark, not 4,000), which counts with hosts that limit requests.
- **HTTP/2 over long links.** A download from a server that only speaks HTTP/2 lets the flow-control window grow with the link, where the fixed windows held it to about 5 MB per round trip: 22.5 MB/s instead of 17.7 at a 100 ms round trip in the speed benchmark.
- **A site's best connection count stays under its cap.** A download that settled on one connection more than the host serves at once (a slot it had just freed still counted when a request was refused) no longer makes the next download from that site start there.
- **Speed benchmark in CI.** `speedbench.rs` times downloads over simulated links (a LAN, caps per connection and per user, a long link, a lossy one, a host that limits requests, 2,000 small files, HTTP/2 over a 100 ms round trip), and the new `speed` job runs it on every push and fails when a scenario falls under its floor in `bench/sim-thresholds.json`. See `bench/README.md`.
- **Internet Archive collections, searches and uploads.** A collection's page, a search (`archive.org/search?query=...`, `advancedsearch.php`) or an account's uploads (`details/@name`) adds each item's files, read through archive.org's scraping API, one item a second. One run lists at most 100 new items (`--max-items`), says so, and goes on with the next ones when the link is added again; items already downloaded are skipped without a request. `--formats` (GUI: "Archive formats") picks an item's files by format or extension, `original` or `derivative`.
- **Internet Archive items from their torrents too.** With the swarm on and no proxy, an item whose chosen files come to 100 MiB or more takes those its `<item>_archive.torrent` holds as its metadata lists them (path, size, SHA-1 and MD5) from the torrent's web seeds and swarm at once, in one download; files the torrent lacks or has otherwise come over HTTP. They arrive in a hidden `.<item>.torrent` folder and move into the item's folder once complete; such a torrent does not seed, and three download at once, so a collection does not open a swarm per item. `--no-p2p` (GUI: BitTorrent off) keeps items on HTTP. This is an experiment, off unless the environment variable `ENDO_WEB_SEED_PEERS` is set: against archive.org it measured several times slower than its files over HTTP first, which stays the default.
- **Archive sites.** Kiwix ZIM files and folders download from every mirror their Metalink names, checked by its hashes (with the swarm on and no proxy, one of 100 MiB or more whose torrent holds the same bytes, by the Metalink's piece hashes, from the torrent's swarm and every mirror at once), and a library.kiwix.org book's page is its ZIM file; a Wikimedia dumps run is its finished files, with the documented mirrors that hold the same SHA-1; a Project Gutenberg book is its formats from Gutenberg's HTTPS mirrors; an arXiv paper is its PDF and source from `export.arxiv.org`, over one connection, one request every 3 seconds; Zenodo records, Figshare articles and Dataverse datasets are their files with MD5s; a Software Heritage ID is the tarball its vault cooks; a Common Crawl `*.paths.gz` is its files, 100 a run.
- **Wayback Machine.** A capture's link downloads the bytes captured, not the rewritten page. A listing (`web/*/<url>*`, a CDX query, or `--wayback` with `--wayback-from`, `--wayback-to` and `--wayback-filter`) adds one capture per content into `host/path/timestamp/`, each checked against the archive's SHA-1, at most 500 new ones a run, with `wayback-manifest.tsv` in the CLI.
- **`--mirror` copies a web site to browse offline (CLI).** The pages under the link's folder, two links deep (`--mirror-depth`), with `--mirror-requisites` their style sheets, scripts and images, links made relative; it honours robots.txt and its Crawl-delay, asks one thing a second (`--mirror-delay`), stops at 500 pages and 1 GiB, and keeps `mirror-manifest.json` with each file's SHA-256, so a stopped run goes on where it stopped.
- **A pause between requests where a site asks for one.** A site can ask for a gap between requests that downloads keep too, all of them to that site together: arXiv's export host one request every 3 seconds, the Wayback Machine one every 4 (its captures were held to two at a time before, which still let them come faster than it asks).
- **Polite listings.** Every listing above paces its requests per site, rests a host that answers 429 or 503 for as long as it asks (the rest downloads to it share), and identifies with the app's own user agent.

## 2.0.0 (2026-11-15)

- **Extension: big downloads go to the app whatever their type.** With "Send browser downloads to the app" on, a download of 50 MB or more goes to the app whatever its type ("Any file from", 0 turns it off): a 5 GB `.dat` no longer stays in the browser. The file types decide below that, and their default list is longer (`.dat`, `.bin`, `.vhdx`, `.qcow2`, `.safetensors`, `.gguf`, more video, audio, e-book and font types); a list you edited is kept. "Send everything" sends every download of at least the minimum size, "Always from these sites" a site's downloads whatever their type or size. A captured download now goes with the other headers the browser sent for it (Authorization among them), and the app is started when it is not running ("Start the app when needed", on by default).
- **Extension: why a download stayed in the browser.** The popup's new Downloads view lists the last 20 browser downloads with where each went and why, "Send to app" for one that stayed, and Always send / Never for the tab's site. A file the page made itself (`blob:` or `data:`) offers "Send page" when the app can take the page it came from. The list stays in the browser for the session.
- **Extension: more of what a page has.** The popup lists the videos a page names but has not played (`og:video`, JSON-LD, lazy `data-src` sources), finds `.m4v`, `.mov`, `.m4a`, `.aac`, `.flac`, `.wav` and `.opus` served with no type, and keeps the page's subtitle files, which "Subtitles (N)" sends beside the video under its name. A live DASH stream is marked LIVE, one with DRM is marked DRM, and a page that gives its video DRM keys says so at the top of the popup. The Links view has a Torrents type, with `.torrent` and magnet links (the app takes magnets as links now), and "Full-size images", which ticks each image's linked original or largest size.
- **Extension: the app's downloads, and pages the app can take.** The Downloads view shows the app's downloads with their progress, Pause, Resume and Remove. The popup asks the app what it makes of a page: a page of any site its video engine knows gets the media card, a file host's or folder's page puts "Download this page" first, and any other page offers "Ask the app for a video on this page".
- **Extension: a click or a key from anywhere.** A Download button shows over a video while the pointer is on it (not on YouTube, which has its own; "Show a Download button on videos" turns it off). Alt+Shift+D sends the page's best video, and "Send the videos of every open tab" does it for every tab, after a count and a second click. The context menu also sends images and the links in selected text. Settings can be exported to a file and imported from one.

- **Servers that limit how fast requests come.** A download from one stalled and failed, and a batch from one stalled: all its connections asked at once, and each refused one (429 or 503) waited alone while the others kept asking, until the server shut the computer out. Now a new download opens its connections in rounds, twice as many each time the server answered; a refusal rests the whole server for as long as its Retry-After asks, for every download and probe to it, and requests then come back one at a time. A server that stops answering right after refusing us is waited out (5 s, doubling up to a minute, for up to 10 minutes after the refusal) without using up retries, and a probe waits for a busy server for up to 5 minutes instead of 2.

- **Send shares.** Links of the open-source Send (`https://host/download/<id>/#<key>`) download and decrypt their file, each encrypted record checked before it is written; the key stays on this computer and out of the history. Shares with a password are not supported yet.

- **Container images.** A public image on Docker Hub, ghcr.io or Quay (`docker.io/library/alpine:3.20`, its web page, or `docker://` on any registry) downloads into an OCI image layout folder that skopeo and podman load as it is, and docker as a tar of it: this machine's Linux build or the one `--platform` names, every layer checked against its digest, with the registry's anonymous token, fetched again when it expires and never sent to the CDN.

- **SFTP.** `sftp://user[:password]@host/path` links download over SSH as FTP ones do, over several connections; a folder link adds one download per file under it. Sign-in is by the link's password or a private key file (`--ssh-key`, with its passphrase asked for when it is encrypted; GUI: Settings > Debrid & hosts). A server's host key is trusted the first time and kept in `known_hosts` in the app's data folder; a key that changed is refused, every time, until you remove the old one.

- **Private S3 buckets.** With an access key (`--s3-access-key` and `--s3-secret-key`, a session token for temporary credentials, a region; GUI: Settings > Debrid & hosts), requests to Amazon S3 and the S3-compatible Wasabi, Backblaze B2, DigitalOcean Spaces and R2 are signed, so private buckets list and their files download; `--s3-endpoint` adds an S3-compatible server on a host of its own, such as MinIO, whose folder links then list too. The key goes to those servers alone and is never saved with the queue or in the history; a server whose clock is off is signed for at its own time.

- **App: update from the copy on disk.** A link whose earlier download's file is still on disk offers "Update from the copy on disk": downloaded again in its place only if the server has a newer one, reusing what the copy holds where the server publishes block checksums. Advanced options take an older version to reuse (Browse…), and the download's page says how much was reused ("Reused 3.1 GiB of the old file, downloaded 240 MiB"; the CLI prints it too).

- **Torrents with web seeds, then the swarm.** With BitTorrent on, a `.torrent` whose files have HTTP web seeds downloads them from the seeds first, checked by the torrent's piece hashes, and then fetches from peers only the pieces still bad or missing (one after the other, not at once). With BitTorrent off, a web-seeded file is now checked by the torrent's piece hashes, and bad pieces come again from another seed.

- **Only what changed of a new version.** With an older version of a file on disk (`--delta-from FILE` in the CLI, or the file `-N` replaces), the blocks it still holds are copied from it and only the rest is downloaded, when the server publishes the new version's block checksums: a metalink's piece hashes, or a zsync file (beside the link, or `--zsync URL`). The result is checked whole against the zsync file's SHA-1 or your checksum; without published block checksums the file is downloaded whole, as before.

- **Autopilot for connections.** Each download finds its own number of connections as it goes: more while they make it faster (twice as many while each one added keeps its speed), and the fewest that reach what the server or your line allows when more do not help, never past what a server that refuses more (429/503) serves at once. A download starts with at most 8 unless the server caps each connection or downloads from it were fastest with more, so a server that serves few well is not hit with 64 at once. A connection slowing down before a stall now makes way for a new one even with fewer than four running. The download's page says why it has the connections it has (Autopilot), as does `-v` in the CLI; the setting is called Autopilot. `hosts.json` also keeps the speed a site held downloads to, and your line's top speed.
- **App: priorities share the speed limit.** Under a speed limit, running downloads share it by priority instead of first come first served: a High one gets twice a Normal one's part and a Low one half, a download that takes less leaves the rest to the others, and one with a few seconds left gets a little more.
- **CLI: `--json` says why.** Each item has an `autopilot` key: why a download over ranges ended with the connections it had, as `-v` says (`null` for one that had none to choose).
- **Sites that refuse HTTP/1.1 are remembered.** Once a site refused HTTP/1.1 and a download from it went over HTTP/2, the next one asks over HTTP/2 at once, without a failed try first. A site's offer of HTTP/3 (`Alt-Svc`) is kept too, for when the app speaks HTTP/3; `hosts.json` keeps which, by site name.
- **A slow address is tried again.** Of a server's several addresses, one where a connection stays far slower than the others is now left alone for 30 s and then measured again, instead of for the rest of the download: it may be busy only for a while.
- **The Metalink a server names checks the file.** When a server's answer points to a Metalink for its file (`Link: rel=describedby`) and you gave no checksum, the finished file is checked against that Metalink's hash of the whole file, as against a site's published checksum: a mismatch fails the download.
- **Files out of a remote ZIP.** The files listed by "See what's inside" now have boxes to tick, with All, and Download selected downloads only those, each into its folder under the save folder: read by range, unpacked as it arrives and checked against its CRC-32. The CLI does the same with `--zip-file PATTERN` (with `--preview`, it lists only those). Stored and deflated files work, ZIP64 too; an encrypted file, or one packed another way, says so.
- **Mirrors a server names.** A server that names other copies of its file (RFC 6249: `Link` headers with `rel=duplicate`, or a Metalink a `rel=describedby` one points to) has them join the download as mirrors do, only if they serve the same file (size and ETag). The Autopilot counts each mirror's connection cap, not only the first's.
- **App: find things faster.** Settings has a search box and starts with the common settings (All settings shows the rest); the Queue's list is narrowed by text in a name or link and by status (Running, Waiting, Failed, Done).
- **App: Undo.** Removing a download, Clear completed and Clear all offer Undo for 8 seconds, in a note at the bottom of the window.
- **App: a first-run welcome** on the Add page with the three steps to a first download, a list of the keyboard shortcuts (F1, or Shortcuts in the sidebar), and empty pages that say what to do.
- **App: plainer words.** Common errors say what to do about them ("The file is no longer at this link…"), a download's workers are called connections, and "resolving" is "connecting".
- **SourceForge:** its links failed, as SourceForge answers the browser User-Agent the app sent with a 403 page; it now gets the app's own, and a file downloads from SourceForge's pick of a mirror and up to five more from the mirror list it gives for that file.
- **Internet Archive items:** an `archive.org/details/<item>` or `/download/<item>` link (or a folder of it, `/download/<item>/<folder>/`) adds one download per file uploaded to the item, with archive.org's size and SHA-1 to check it, leaving out the copies and records archive.org makes.
- **GitLab, Bitbucket, Codeberg, Gitea and Forgejo:** a repository link downloads its default branch as a zip, a folder link adds one download per file (subfolders kept), and a release (or Bitbucket's Downloads) one per asset, as GitHub's do; self-hosted GitLab, Gitea and Forgejo are recognised by their links' paths, and their "view file" links download the file.
- **Nextcloud and ownCloud shares:** a public share link (`/s/<token>`, `/index.php/s/<token>`) on any server that runs one adds one download per file of a shared folder (subfolders kept, with the server's SHA-1 or MD5 where it keeps one), or the shared file; a share with a password opens with it in the link, `https://TOKEN:PASSWORD@host/s/TOKEN`.
- **PyPI:** a project link (`pypi.org/project/<name>/`) adds its latest release's files, and a release link (`/project/<name>/<version>/`) that release's, each with its size and SHA-256; they downloaded the project's web page before.
- **npm:** a package link (`npmjs.com/package/<name>`, `/v/<version>`, scoped packages too) downloads the package's tarball, checked against its SHA-512; it downloaded the package's web page before.
- **crates.io:** a crate link (`crates.io/crates/<name>`, `/<version>`) downloads the crate's `.crate` file with its size and SHA-256; it downloaded the site's web page before.
- **IPFS:** an `ipfs://<cid>` link, a gateway's `/ipfs/<cid>` link or a subdomain gateway's downloads from several public gateways at once as mirrors, checked against the CID when it is the file's own SHA-256; `ipfs://` links were refused, and the gateway list no longer has cloudflare-ipfs.com, closed since 2024.
- **Steam Workshop:** an item link (`steamcommunity.com/sharedfiles/filedetails/?id=...`) downloads the item's file, with its name and size, when Steam's public Web API has one (items stored the older way); a newer item says it comes only through the Steam client, where its page was downloaded before.
- **Bunkr, Cyberdrop and Catbox albums** go to gallery-dl, which reads them, as imgur's do; they downloaded the album's web page before. A Catbox or Litterbox file link was already its file.
- **SwissTransfer:** a transfer link (`swisstransfer.com/d/...`) adds one download per file with its size, folders kept, read from SwissTransfer's public API; one with a password opens with the password pasted with it. It downloaded the transfer's web page before.
- **Telegram:** a public channel's post (`t.me/<channel>/<post>`) downloads the photos and videos its public page shows, an album's all; a photo post was an error before. Files posted in a channel are only in Telegram's app.
- **Public buckets:** an Amazon S3 (`s3://`, virtual-hosted or path-style), Backblaze B2, Wasabi or DigitalOcean Spaces bucket, a Google Cloud Storage bucket (`gs://`, `storage.googleapis.com/<bucket>/`) or an Azure Blob container that anyone may list adds one download per object under its prefix, folders kept, with its size and MD5 where it is one; a private one says it needs its owner's key.
- **WebDAV:** a `webdav://`, `webdavs://`, `dav://` or `davs://` link downloads the file it names, or adds one download per file of the folder it names (subfolders kept), with a sign-in given in the link; these links were refused before.
- Fixed: a progress bar's fill went square when short and the light sweeping over it was cut to a rectangle; both now follow the bar's round ends.
- **Open directories:** a link to a web server's directory index (Apache, nginx, lighttpd, IIS, Caddy, Python's http.server) adds one download per file below it, subfolders kept, with each file's size where the page gives it in bytes; before, the index page itself was downloaded.

Expired segments are skipped as gaps; the free-space guard and "keep what was recorded" rules apply as for other recordings. Media sites are still recorded by yt-dlp.
- **More for streams:** an HLS or DASH download takes its subtitles tracks in the subtitle languages (WebVTT, TTML, `wvtt`, `stpp`), joined into the file with their languages or saved as `<name>.<language>.srt`, or alone with no video and audio; `--sections` keeps the whole segments that overlap its ranges, in every track; parts and segments whose links match ad patterns (`*` for any run) can be left out; `--name-pattern` names a stream download from its height, codec, audio languages, channel, date and more. Subtitle files beside a stream are now `.srt`.
- **Channel lists and TV streams:** an extended M3U of channel links (a `.m3u` link or a local file) becomes one download per channel chosen by name or group patterns, named after it (a playlist of songs stays a file); an MPEG-TS stream with no length, or any channel's, is recorded like a live stream, until it ends, a time or size limit, idle time or a stop, keeping what it recorded.
- **Smooth Streaming:** `.ism/Manifest` links and `application/vnd.ms-sstr+xml` answers go to yt-dlp, a protected one refused first (their `(format=m3u8…)` and `(format=mpd…)` forms are the HLS and DASH they serve, downloaded natively); the browser extension lists them like DASH manifests.

Default options from a config file (`cli.conf` in the data folder, or `--config`), `--doctor` to see what the program runs with, and `--start-at` to start later.
- **CLI tool commands:** `concat` joins files byte by byte, `merge` joins segments with ffmpeg, `mux` puts video, audio and subtitles (files of your own too) into one file, and `doctor` lists the outside tools it finds. `-sv`, `-sa` and `-ss` are short for `--video`, `--audio` and `--subs`, and other common option names (`--select-video`, `--save-dir`, `--save-name`, `--save-pattern`, `--custom-range`, `--ad-keyword`, `--live-record-limit` and more) do the job of the matching option.

- **A server busy at the start** (HTTP 429 or 503 to the first requests, HEAD included) no longer fails the download at once: it is asked again once its `Retry-After` is over, else after 2, 4, 8 and then every 16 s, for up to 2 minutes. A `Retry-After` given as a date is honoured too, not only seconds.
- **Faster with many connections:** a large file's connections all start as soon as the probe answers, instead of after it measured the host, and a chunk about to finish is no longer split for one more request and connection (the bytes a connection had received but not yet written counted as left).

- **Each site's best connection count is remembered across restarts**, with a connection cap it was seen to enforce, for 30 days, in `hosts.json` in the data folder (host names only): the next download from it starts at the count adaptive connections settled on, instead of finding it again.
- **A download's connections are spread over its server's addresses**, when its name has several (a CDN's), as over several networks: an address that fails, or where a connection stays far slower than the others, is dropped. Not through a proxy, and not over FTP. On by default; `--no-spread-addresses`, or "Use the server's addresses" in Settings > Connections & networks, turns it off.
